## 🎯 رؤية المنصة

**بزة** هو أول نظام تشغيل مالي (Financial Operating System) لسوريا — بنية تحتية رقمية موحدة تستبدل النقد بـ"نقود قابلة للبرمجة"، وتصل 18 مليون مواطن داخل سوريا و6 ملايين مغترب عبر منصة واحدة.

### الركائز الأساسية

| الركيزة | الوصف |
|---------|-------|
| **محفظة رقمية** | محافظ متعددة العملات (SYP/USD) بحدود متدرجة T1-T3 |
| **صرف العملات** | محرك آلي بأسعار من مصرف سوريا المركزي، قفل سعر 15 ثانية |
| **شبكة الوكلاء** | إيداع وسحب نقدي وطني عبر 10,000+ وكيل |
| **مقبولية التجار** | QR دفع، روابط دفع، نقاط بيع لجميع الأحجام |
| **الرواتب** | توزيع رقمي للرواتب عبر الشركات والمؤسسات |
| **التحصيلات الحكومية** | ضرائب، رسوم، فواتير، مدفوعات اجتماعية |
| **الحوالات** | استقبال حوالات المغتربين (لبنان، الإمارات، الأردن، ألمانيا) |
| **الادخار والتمويل** | أهداف ادخارية، تمويل متوافق مع الشريعة |
| **البطاقات** | بطاقات مسبقة الدفع افتراضية وفيزيائية |
| **التمويل المفتوح** | Open Finance API لمنظومة الابتكار الخارجي |

### من يخدم؟

| الفئة | العدد المستهدف | الخدمة |
|-------|---------------|--------|
| مواطنون سوريون | 18M | محفظة، تحويل، فواتير، ادخار |
| مغتربون سوريون | 6M | حوالات، دعم عائلات |
| تجار | 50,000 | قبول مدفوعات، تسوية D+1 |
| وكلاء | 10,000 | إيداع/سحب نقدي |
| شركات ومؤسسات | 1,000+ | رواتب، مدفوعات جماعية |
| جهات حكومية | 30+ | تحصيلات، مدفوعات اجتماعية |
| منظمات إنسانية | 50+ | مساعدات، قسائم شرائية |

### تدفق المعاملة المالية

```
المستخدم → التطبيق → Nginx → Module Controller
  → Domain Service (قواعد الأعمال)
    → CFE (Hold → Post → Fee → Ledger)
      → Event Bus (TransactionEvent)
        → Listeners (إشعارات، تحليلات، امتثال)
          → Response (تأكيد، إيصال)
```

## 🔄 سيناريوهات الاستخدام

### السيناريو 1: مستخدم جديد — رحلة الإعداد الكاملة

```
مستخدم جديد (لا حساب بنكي، هاتف ذكي، 5000 ل.س نقدًا)

1. تحميل التطبيق من المتجر
2. إدخال رقم الهاتف (09XX-XXX-XXX)
3. استلام OTP عبر SMS → التحقق
4. إنشاء PIN (6 أرقام)
5. منح الصلاحيات: SMS، الموقع، الكاميرا
6. ← إنشاء المحفظة (رصيد 0 ل.س)
7. العثور على أقرب وكيل (GPS)
8. زيارة الوكيل، إيداع 5000 ل.س نقدًا
9. ← تفعيل Tier 1: محفظة جاهزة!
```

**خطوات تقنية:**
```
POST /auth/register         → رقم الهاتف
POST /auth/verify-otp       → OTP + phone
POST /auth/create-pin       → PIN hash
POST /wallet/create         → ULID wallet (balance=0)
GET  /agent/nearby          ← GPS → top 3 agents
POST /wallet/deposit        → CFE hold → agent confirm → CFE post → Ledger
      ↑ Cash-in event → notification → balance updated
```

### السيناريو 2: تحويل P2P بين الأصدقاء

```
أحمد (دمشق) ← يريد إرسال 10,000 ل.س → ليلى (حلب)

1. أحمد يفتح المحفظة ← يختار "تحويل"
2. يدخل رقم هاتف ليلى أو يختار من جهات الاتصال
3. يدخل المبلغ: 10,000 ل.س
4. يدخل PIN للتأكيد
5. ← CFE: Hold 10,000 ل.س من محفظة أحمد
6. ← CFE: Post 10,000 ل.س إلى محفظة ليلى
7. ← CFE: Fee (0.5% = 50 ل.س) إلى حساب الرسوم
8. ← Ledger: قيد مزدوج (مدين أحمد، دائن ليلى)
9. ليلى تستلم إشعار: "استلمت 10,000 ل.س من أحمد"
```

### السيناريو 4: حوالة مغترب

```
مغترب سوري في الإمارات يرسل $200 لأمه في دمشق

1. المغترب يفتح التطبيق ← "حوالات"
2. يختار الممر: الإمارات → سوريا
3. يدخل اسم المستلم ورقم هاتفه
4. يختار مصدر الأموال ومبرر التحويل
5. المبلغ: $200 ← السعر: 1 USD = 12,500 SYP
6. ← Fee: 1.5% + $2 ثابت
7. ← Compliance hold ($200 < $1K ← تلقائي)
8. ← فحص العقوبات (OFAC) ← نظيف
9. ← تصفية عبر حساب التعليق (Suspense)
10. المستلمة تستلم: 2,490,000 ل.س في محفظتها
11. إشعار SMS: "وصلتك حوالة $200 بقيمة 2,490,000 ل.س"
```

### السيناريو 5: التسوق عبر السوق (Marketplace)

```
مستخدم يشتري هاتفًا من متجر في السوق

1. تصفح المنتجات ← اختيار هاتف بقيمة 500,000 ل.س
2. ← إنشاء طلب + الضمان (Escrow)
3. ← CFE: Hold 500,000 ل.س في حساب الضمان
4. التاجر يستلم إشعار: "تأكيد الطلب"
5. التاجر يشحن الهاتف عبر شركة شحن
6. المستخدم يستلم الهاتف ← تأكيد الاستلام
7. ← CFE: Release 500,000 ل.س → حساب التاجر
8. ← Commission: 3% = 15,000 ل.س (بزة)
9. ← Settlement: D+1 للتاجر
```

## 🏛️ النظام المالي الأساسي

### Core Financial Engine (CFE)

**قلب بزة المالي** — كل حركة أموال تمر عبر CFE، ولا توجد أي وحدة تستطيع كتابة الرصيد مباشرة.

| المحرك | الوظيفة | الحالات |
|--------|---------|---------|
| PostingEngine | تنفيذ الحركات المالية | initiated → pending → completed / failed |
| FeeEngine | حساب وتطبيق الرسوم | assessed → applied → reversed |
| HoldEngine | تجميد الأموال مؤقتًا | placed → released / expired / captured |
| ReversalEngine | عكس الحركات الخاطئة | initiated → approved → completed |

### Ledger (دفتر الأستاذ)

**مصدر الحقيقة الوحيد** — سجل محاسبي بقيد مزدوج، إلحاقي فقط (Append-only, WORM).

```
13 حسابًا أوليًا:
├── 1000 الأصول (Assets)
│   ├── 1100 محافظ العملاء
│   ├── 1200 محافظ الوكلاء
│   ├── 1300 حساب التعليق (Suspense)
│   └── 1400 احتياطي السيولة
├── 2000 الخصوم (Liabilities)
│   ├── 2100 مستحق للتجار
│   └── 2200 مستحق للحكومة
├── 3000 حقوق الملكية (Equity)
├── 4000 الإيرادات (Revenue)
│   ├── 4100 رسوم المعاملات
│   └── 4200 فارق العملة
└── 5000 المصروفات (Expenses)
```

**القواعد:**
- لا UPDATE أو DELETE على journal_entries أو journal_lines
- الأخطاء ← إدراج قيد عكسي (Reversal Entry)
- كل حركة مالية ← قيد مزدوج (Debit/Credit)

### القواعد المعمارية (غير قابلة للتفاوض)

| القاعدة | الشرح |
|---------|-------|
| **G-001** | لا وصول مباشر إلى Ledger من أي وحدة غير CFE |
| **G-002** | كل حركة مالية → CFE. لا استثناءات |
| **G-003** | Controller → Service → Repository (طبقات صارمة) |
| **G-004** | Money = bigint (أجزاء صغيرة) + Value Object. ممنوع float |
| **G-005** | Ledger إلحاقي فقط — WORM |
| **G-007** | ULID لجميع المفاتيح الأساسية |
| **G-008** | التواصل بين الوحدات عبر Events فقط |
| **G-010** | اختبار Feature لكل نقطة نهاية عامة |

## 🔐 الأمان والامتثال

### نموذج الثقة (Zero Trust)

```
┌──────────────────────────────────────────────┐
│               ZERO TRUST ARCHITECTURE         │
│                                               │
│  1. المصادقة: JWT + OTP + PIN + Biometric    │
│  2. التفويض: RBAC (دور) + ABAC (سياسة)       │
│  3. ربط الجهاز: Device Binding + Fingerprint │
│  4. تشفير: AES-256-GCM في الراحة، TLS 1.3    │
│     في النقل                                   │
│  5. الامتثال: AML/CFT ← فحص OFAC + SDN       │
│  6. الاحتيال: 20+ قاعدة، تسجيل 0-1000         │
│  7. المراجعة: سجل تدقيق كامل (Ledger WORM)    │
└──────────────────────────────────────────────┘
```

### الأدوار (RBAC)

| الدور | الصلاحيات |
|-------|----------|
| Super Admin | كل شيء |
| Compliance | KYC review، عقوبات، بلاغات |
| Finance | تسوية، رسوم، تقارير مالية |
| Agent Manager | وكلاء، عمولات، سيولة |
| Support | مستخدمين، معاملات، نزاعات |

### الامتثال المحلي

| المتطلب | التطبيق في بزة |
|---------|---------------|
| AML/CFT | ← فحص OFAC + SDN لكل حوالة > $1,000 |
| مكافحة الاحتيال | ← 20+ قاعدة خوارزمية + بصمة جهاز |
| حماية البيانات | ← تشفير + فصل البيانات + سجل تدقيق |
| الشريعة الإسلامية | ← عقود مرابحة + تكافل + زكاة |
| مصرف سوريا المركزي | ← تغذية أسعار CBS + تقارير دورية |
