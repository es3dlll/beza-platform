# FORK_SUBAGENT — بروتوكول استدعاء الوكلاء الفرعيين

> يحدد هذا البروتوكول **متى وكيف** يستدعي وكيل فرعي (subagent) وكلاء فرعيين آخرين للتنفيذ المتوازي، وكيفية دمج النتائج.

---

## 1. متى يستخدم الـ Fork؟

| الحالة | مثال | النوع |
|--------|------|-------|
| مهام مستقلة متعددة | Backend يحتاج API + Migration + Tests في نفس الوقت | `parallel` |
| مهمة تحتاج خبير مختلف | Frontend يحتاج QA-UI لاختبار واجهة | `dependent` |
| مراجعة قبل التسليم | أي وكيل يحتاج مراجعة أمنية من Pentest | `supervised` |
| توثيق المخرجات | أي وكيل يحتاج Doc لكتابة التوثيق | `parallel` |

---

## 2. أنواع الـ Fork

| النوع | الوصف | دمج النتائج |
|-------|-------|-------------|
| `parallel` | Fork وإطلاق — لا تنتظر النتيجة | تُجمع النتائج لاحقاً عند اكتمال الجميع |
| `dependent` | Fork وانتظر النتيجة قبل الاستمرار | نتيجة المهمة المforkة مطلوبة لاستكمال المهمة الأم |
| `supervised` | Fork مع مراجعة الوالد لكل خطوة | الوالد يراجع مخرجات المfork قبل اعتمادها |

---

## 3. قواعد الوراثة (Inheritance)

عند fork وكيل فرعي، يرث المfork تلقائياً:

1. **دور الوالد** — يعرف من استدعاه
2. **بوابات الجودة** — يمر بنفس الـ 6 Gates
3. **القوانين الخاصة** — قوانين الوالد + قوانينه الخاصة
4. **السياق** — يحصل على ملخص السياق الحالي من الوالد

---

## 4. بروتوكول Fork

### 4.1 الطلب
```
FORK: <اسم الوكيل>
TYPE: parallel | dependent | supervised
CONTEXT: <ملخص السياق والمتطلبات>
EXPECTED: <المخرجات المتوقعة>
DEADLINE: <الوقت المقدر>
```

### 4.2 التنفيذ
يقوم الوكيل المfork بتنفيذ مهمته عبر pipeline الـ 6 مراحل:
1. فحص 🔎 — يفهم المهمة
2. اختبار أولي 🧪 — يتحقق من البيئة
3. فحص موسع 🔬 — يحلل المخاطر
4. تطوير ⚒️ — ينفذ
5. اختبار نهائي ✅ — يختبر
6. تأكيد 🏁 — يسلم

### 4.3 التسليم
```
FORK_RESULT:
  AGENT: <اسم الوكيل>
  STATUS: passed | failed | partial
  OUTPUTS: <روابط/مسارات المخرجات>
  REPORT: <ملخص الإنجاز>
  ISSUES: <أي مشاكل أو تحذيرات>
```

---

## 5. حل النزاعات

| الحالة | الإجراء |
|--------|---------|
| مخرجات غير متوقعة | الوالد يطلب توضيحاً من المfork |
| فشل في الاختبارات | المfork يصلح ويعيد التسليم |
| تعارض مع دستور الوالد | يُرفع إلى CEO للبت |
| المfork لا يستطيع الإكمال | يعود إلى الوالد مع تقرير المشكلة |

---

## 6. المبادئ الأساسية

- **لا Fork بدون سياق** — كل fork يجب أن يتضمن سياقاً كافياً
- **المسؤولية تبقى مع الوالد** — الوالد مسؤول عن مخرجات المfork
- **CEO هو الملاذ الأخير** — أي نزاع لا يُحل يرفع إلى CEO
- **التوثيق إلزامي** — كل fork يُوثق في تقرير المهمة النهائي
