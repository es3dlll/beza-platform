# 01 - فكرة العمل وسيناريو المستخدم — المصادقة الثنائية (2FA)

## الفكرة الأساسية

المستخدم "علي" يريد تفعيل طبقة أمان إضافية عبر Google Authenticator:
1. **تفعيل 2FA** — مسح QR code باستخدام Google Authenticator
2. **التحقق** — إدخال رمز TOTP (6 أرقام) لتأكيد التفعيل
3. **إجباري للمعاملات الكبيرة** — > 1,000 USD
4. **اختياري للمعاملات الصغيرة**

## سيناريو المستخدم (User Story)

```
بصفتي: مستخدم في Beza
أريد: تفعيل المصادقة الثنائية لحسابي
لكي: أحمي أموالي من الوصول غير المصرح به
```

## قبول السيناريو (Acceptance Criteria)

| # | الشرط | الحالة |
|---|-------|--------|
| 1 | الدخول إلى إعدادات 2FA | OK |
| 2 | الضغط على "تفعيل" | OK |
| 3 | توليد secret key عبر Google2FA | OK |
| 4 | عرض QR code (base64) | OK |
| 5 | مسح QR code بتطبيق Authenticator | OK |
| 6 | إدخال رمز TOTP (6 أرقام) | OK |
| 7 | التحقق من الرمز وتأكيد التفعيل | OK |
| 8 | تخزين secret مشفراً في DB | OK |
| 9 | two_factor_confirmed = true | OK |
| 10 | إنشاء رموز استرداد (recovery codes) | OK |

## تدفق الشاشات (User Flow)

```
[الإعدادات] → [2FA] → [تفعيل] → [مسح QR] → [إدخال رمز] → [مفعل]
```

## لماذا 2FA إجباري للمبالغ الكبيرة؟

1. **الامتثال** — متطلبات الجهات التنظيمية للمدفوعات الرقمية
2. **حماية المستخدم** — منع عمليات الاحتيال الكبيرة
3. **تأمين إضافي** — حتى لو سُرقت كلمة المرور، الرمز الثاني مطلوب
