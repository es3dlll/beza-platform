# 01 - فكرة العمل وسيناريو المستخدم (Business Idea) — تسجيل الدخول (Login)

## الفكرة الأساسية

المستخدم "علي" لديه حساب في Beza ويريد الدخول للتطبيق. العملية يجب أن تكون:
1. **آمنة** — التحقق من كلمة المرور + حماية من brute force
2. **سريعة** — استجابة < 500ms
3. **متسقة** — تحديث last_login و device_id

## سيناريو المستخدم (User Story)

```
بصفتي: مستخدم في Beza
أريد: تسجيل الدخول بحسابي
لكي: أتمكن من استخدام خدمات المنصة
```

## قبول السيناريو (Acceptance Criteria)

| # | الشرط | الحالة |
|---|-------|--------|
| 1 | إدخال رقم الهاتف | إجباري |
| 2 | إدخال كلمة المرور | إجباري |
| 3 | البحث عن المستخدم بـ phone | OK |
| 4 | التحقق من كلمة المرور (Hash::check) | OK |
| 5 | التحقق من أن المستخدم غير suspended | OK |
| 6 | تحديث last_login_at | OK |
| 7 | تحديث last_login_ip | OK |
| 8 | تحديث device_id | OK |
| 9 | حذف التوكنات القديمة | OK |
| 10 | إنشاء توكن جديد | OK |
| 11 | قفل الحساب بعد 5 محاولات فاشلة | OK |
| 12 | إلغاء القفل بعد 15 دقيقة | OK |

## تدفق الشاشات (User Flow)

```
[ترحيب] → [دخول] → [إدخال هاتف + كلمة سر] → [تحقق 2FA?] → [الرئيسية]
```

## لماذا حذف التوكنات القديمة؟

1. **منع التراكم** — قد يملك المستخدم مئات التوكنات مع مرور الوقت
2. **الأمان** — إذا سُرِق جهاز قديم، توكنه ملغي
3. **الحد من الاستخدام** — JWT ليس مصمماً للتوكنات غير المحدودة
