# 19 - حالات الحافة (Edge Cases)

## 1. توكن محذوف مسبقاً

**المشكلة**: مستخدم يضغط "تسجيل خروج" مرتين بسرعة.

**الحل**: JWT invalidate يتجاهل التوكن الملغي مسبقاً.

```php
public function logout(User $user): void
{
    JWTAuth::invalidate(true);
    // JWT يتجاهل التوكن الملغي مسبقاً
}
```

## 2. تسجيل الخروج من جهاز معطل

**المشكلة**: فقدان الجهاز — المستخدم لا يمكنه الوصول ليقوم بتسجيل الخروج.

**الحل**: "تسجيل خروج من كل الأجهزة" عبر واجهة الويب (بعد تسجيل الدخول بكلمة مرور).

## 3. تزامن حذف التوكن

**المشكلة**: طلبين متزامنين لحذف نفس التوكن.

**الحل**: JWTAuth::invalidate() يستخدم blacklist — التوكن الملغي مسبقاً يتجاهل.

## 4. استمرار الجلسة بعد حذف التوكن

**المشكلة**: التطبيق لا يمسح التوكن من التخزين المحلي بعد logout.

**الحل**: يجب على الـ Frontend حذف التوكن من localStorage/secure storage بعد استجابة 200.

## 5. Logout-all يمسح التوكن الحالي أيضاً

**المشكلة**: المستخدم يريد الخروج من الأجهزة الأخرى فقط.

**الحل**: JWT هو stateless — تسجيل الخروج يؤثر على التوكن الحالي فقط.

## جدول ملخص حالات الحافة

| # | الحالة | النتيجة | مستوى المعالجة |
|---|--------|---------|---------------|
| 1 | توكن ملغي مسبقاً | تجاهل (no-op) | Application |
| 2 | جهاز مفقود | خروج من كل الأجهزة | Application |
| 3 | حذف متزامن | الطلب الثاني يتجاهل | JWT Blacklist |
| 4 | استمرار التوكن محلياً | يجب على Frontend المسح | Frontend |
| 5 | Logout-all بدون الحالي | JWT Stateless — لا يؤثر إلا على الحالي | Application |
