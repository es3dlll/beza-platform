# 14 - المعاملات الحمضية (Database Transactions & ACID)

**الرمز التشغيلي:** SY2-health  
**النوع:** توثيق المعاملات (Transaction Documentation)

---

## خلاصة (Summary)

عملية SY2-health **لا تستخدم أي معاملات قاعدة بيانات** ولا تتطلب خصائص ACID.

---

## لماذا لا حاجة للمعاملات؟ (Why No Transactions Needed?)

| خاصية ACID | هل تستخدم؟ | الشرح |
|-----------|-----------|--------|
| **Atomicity** (الذرية) | لا | لا توجد عمليات كتابة متعددة في قاعدة البيانات |
| **Consistency** (الاتساق) | لا | لا توجد بيانات تخزن في DB، كل النتائج مؤقتة |
| **Isolation** (العزل) | لا | لا توجد عمليات متزامنة على نفس البيانات |
| **Durability** (الديمومة) | لا | النتائج مؤقتة ولا تحتاج تخزين دائم |

---

## أين تذهب البيانات؟ (Where Does Data Go?)

جميع البيانات في عملية SY2-health هي بيانات وقتية:

```
نتائج الفحص
    │
    ├── 70% ← تعرض مباشرة للمستخدم (JSON response)
    ├── 20% ← تخزن مؤقتاً في Redis (30 ثانية)
    └── 10% ← تسجل في ملفات السجل (storage/logs/health-*.log)
```

**لا يتم تخزين أي شيء في قاعدة البيانات العلائقية (MySQL).**

---

## هل نحتاج معاملات للكاش؟ (Do We Need Cache Transactions?)

لا، لأن:

1. **عمليات الكاش بسيطة:** `put` و `get` و `forget` لا تحتاج معاملات.
2. **Redis يدعم atomicity طبيعياً:** `SET` و `GET` عمليات ذرية بطبيعتها.
3. **التخزين المؤقت اختياري:** لو فشل تخزين النتيجة في الكاش، الفحص لا يزال ناجحاً.

```php
<?php
// ترجمة: مثال - لا حاجة لمعاملات مع الكاش

// هذه العملية لا تحتاج transaction:
Cache::put('health:general', $report, 30);

// حتى لو فشلت، الفحص اكتمل بنجاح:
if (!Cache::has('health:general')) {
    // ترجمة: فقط نسجل تحذيراً
    Log::warning('فشل تخزين نتيجة الفحص في الكاش');
}
```

---

## هل نحتاج معاملات للسجلات؟ (Do We Need Log Transactions?)

لا، لأن:

1. **Monolog يكتب إلى الملفات:** كتابة ملفات السجل هي عملية IO بسيطة.
2. **فشل كتابة السجل لا يؤثر على الاستجابة:** حتى لو تعذرت كتابة السجل، المستخدم لا يزال يتلقى الاستجابة.

```php
<?php
// ترجمة: حتى لو فشلت كتابة السجل، المستخدم لا يتأثر

try {
    Log::channel('health')->info('تم الفحص الصحي');
} catch (\Exception $e) {
    // ترجمة: تجاهل فشل كتابة السجل - لا نريد إيقاف النظام بسبب فشل تسجيل
}
```

---

## سيناريو hypothetical: لو احتجنا تتبع تاريخي

في المستقبل، لو قررنا إضافة جدول `health_check_logs`، سنحتاج معاملات عند:

```php
<?php
// ترجمة: سيناريو افتراضي فقط - غير مطبق حالياً

use Illuminate\Support\Facades\DB;

DB::transaction(function () use ($results, $overallStatus) {
    // ترجمة: إدخال سجل الفحص الرئيسي
    $logId = DB::table('health_check_logs')->insertGetId([
        'overall_status' => $overallStatus,
        'checked_at'     => now(),
    ]);

    // ترجمة: إدخال تفاصيل كل خدمة
    foreach ($results as $service) {
        DB::table('health_check_details')->insert([
            'log_id'         => $logId,
            'service_name'   => $service->name,
            'status'         => $service->status,
            'latency_ms'     => $service->latency_ms,
            'error_message'  => $service->error,
        ]);
    }
    // ترجمة: إذا فشلت أي عملية، سيتم التراجع عن كل الإدخالات تلقائياً
});
```

**لكن هذا غير مطبق حالياً** لأن:
- يضيف تعقيداً غير ضروري
- يستهلك مساحة تخزين
- يمكن استبداله بأدوات خارجية مثل Grafana

---

## الخلاصة (Conclusion)

```
┌────────────────────────────────────────────┐
│              SY2-health                     │
│                                            │
│  ACID Transactions: ❌ غير مطلوبة           │
│  Database Writes:    ❌ لا توجد              │
│  Cache Operations:   ✅ ذرية تلقائياً       │
│  Log Operations:     ✅ تسامحية مع الخطأ    │
└────────────────────────────────────────────┘
```

لا توجد معاملات قاعدة بيانات في عملية SY2-health. النظام يعتمد على البيانات المؤقتة والتخزين في الذاكرة (Redis/file cache) وكلها لا تحتاج ACID.
