# 01 - فكرة العمل وسيناريو المستخدم (Business Idea & User Scenario)

## الفكرة الأساسية

دفع الفواتير في منصة Beza. 1. الاستعلام عن الفاتورة → 2. عرض المبلغ → 3. تأكيد الدفع → 4. خصم + تسوية مع مزود الخدمة

## سيناريو المستخدم (User Story)

```
بصفتي: مستخدم في Beza
أريد: دفع فواتير الخدمات (كهرباء، ماء، هاتف، إنترنت)
لكي: أسدد فواتيري بسرعة من محفظتي
```

## قبول السيناريو (Acceptance Criteria)

| # | الشرط | دفع الفواتير | الحالة |
|---|-------|--------|--------|
| 1 | اختيار نوع الفاتورة | bill_type | إجباري |
| 2 | إدخال رقم الفاتورة | bill_number | إجباري |
| 3 | الاستعلام عن الفاتورة | inquiry | إجباري |
| 4 | عرض المبلغ | display_amount | إجباري |
| 5 | تأكيد الدفع | confirm | إجباري |
| 6 | خصم من المحفظة | deduct | atomic |

## تدفق الشاشات (User Flow)

```
1. الاستعلام عن الفاتورة →
│
 2. عرض المبلغ →
│
 3. تأكيد الدفع →
│
 4. خصم + تسوية مع مزود الخدمة
```

## القواعد الأساسية

- أنواع الفواتير: كهرباء، ماء، هاتف، إنترنت
- يتم الاستعلام عن الفاتورة قبل الدفع
- يتم عرض المبلغ المستحق للتأكيد
- الخصم يكون فورياً من المحفظة
- التسوية مع مزود الخدمة قد تستغرق وقتاً
