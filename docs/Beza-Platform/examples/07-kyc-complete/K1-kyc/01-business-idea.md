# 01 - فكرة العمل وسيناريو المستخدم (Business Idea & User Scenario)

## الفكرة الأساسية

المستخدم "ليلى" تريد رفع حد محفظتها في Beza. حالياً حدها 100 USD لأنها لم تؤكد هويتها. ترفع وثائق KYC: صورة الهوية الأمامية والخلفية، سيلفي، وإثبات عنوان.

1. **امتثال تنظيمي** — متطلبات AML/KYC الإلزامية
2. **أتمتة** — فحص أولي تلقائي للوثائق
3. **مراجعة بشرية** — Admin يراجع الوثائق يدوياً
4. **رفع الحدود** — بعد التحقق، ترفع القيود

## سيناريو المستخدم (User Story)

```
بصفتي: مستخدم في Beza
أريد: تقديم وثائق هويتي للتحقق
لكي: أتمكن من استخدام المنصة بدون حدود ويصبح حسابي موثوقاً
```

## قبول السيناريو (Acceptance Criteria)

| # | الشرط | الحالة |
|---|-------|--------|
| 1 | المستخدم يسجل الدخول | إجباري |
| 2 | رفع front_id (صورة الهوية الأمامية) | إجباري |
| 3 | رفع back_id (صورة الهوية الخلفية) | إجباري |
| 4 | رفع selfie (صورة شخصية) | إجباري |
| 5 | رفع address_proof (إثبات عنوان) | إجباري |
| 6 | الفحص التلقائي لدقة الصور | auto |
| 7 | رفض تلقائي إذا كانت الصور منخفضة الدقة | auto |
| 8 | مراجعة يدوية من Admin | manual |
| 9 | تحديث kyc_status إلى verified/rejected | update |
| 10 | إشعار المستخدم بنتيجة المراجعة | notification |

## لماذا KYC إلزامي؟

1. **مكافحة غسل الأموال (AML)**: متطلبات قانونية دولية
2. **حماية المنصة**: منع الاحتيال والحسابات الوهمية
3. **حماية المستخدمين**: ضمان هوية جميع الأطراف
4. **الحدود التنظيمية**: بدون KYC الحد الأقصى 100 USD

## تدفق الشاشات (User Flow)

```
[الإعدادات] → [KYC] → [رفع الوثائق] → [قيد المراجعة] → [تم التحقق]
                                                          ↕
                                                    [رفض + إعادة رفع]
```
