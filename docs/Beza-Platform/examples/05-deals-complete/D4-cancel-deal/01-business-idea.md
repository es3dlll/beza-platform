# 01 - فكرة العمل وسيناريو المستخدم (Business Idea & User Scenario)

## الفكرة الأساسية

تعذرت صفقة "تجارة شحنات" لأسباب لوجستية. Admin يضطر لإلغاء الصفقة وإرجاع المبالغ للمستثمرين. المبلغ الإجمالي 45,000 USD موزع على 25 مستثمراً.

1. **إلغاء مُدار** — Admin يلغي الصفقة مع ذكر السبب
2. **استرجاع كامل** — كل مستثمر يسترد كامل مبلغه
3. **معالجة ذرية** — DB::transaction تضمن عدم فقدان أي مبلغ
4. **إشعارات** — كل مستثمر يتلقى إشعاراً بالاسترجاع

## سيناريو المستخدم (User Story)

```
بصفتي: Admin في منصة Beza
أريد: إلغاء صفقة وإعادة المبالغ للمستثمرين
لكي: يسترد المستثمرون أموالهم بالكامل في حال تعذرت الصفقة
```

## قبول السيناريو (Acceptance Criteria)

| # | الشرط | الحالة |
|---|-------|--------|
| 1 | Admin يسجل الدخول | إجباري |
| 2 | Admin يحدد سبب الإلغاء | إجباري |
| 3 | التحقق من أن الصفقة غير مكتملة | business rule |
| 4 | إعادة المبلغ لكل مستثمر | DB::transaction |
| 5 | تسجيل معاملات refund لكل مستثمر | audit |
| 6 | إلغاء تجميد الأرصدة | atomic |
| 7 | تغيير حالة الصفقة إلى cancelled | atomic |
| 8 | إرسال إشعار لكل مستثمر | notification |

## لماذا الاسترجاع الكامل؟

1. **الثقة**: المستثمر يثق أن أمواله في أيدٍ أمينة
2. **الشفافية**: إظهار سبب الإلغاء بوضوح
3. **الامتثال**: متطلبات قانونية في التمويل الجماعي

## تدفق الشاشات (User Flow)

```
[لوحة Admin] → [إلغاء صفقة] → [إدخال سبب] → [تأكيد] → [استرجاع تلقائي]
```
