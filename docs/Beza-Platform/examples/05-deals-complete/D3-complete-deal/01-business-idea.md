# 01 - فكرة العمل وسيناريو المستخدم (Business Idea & User Scenario)

## الفكرة الأساسية

اكتملت صفقة "تجارة شحنات إلكترونية" وحققت أرباحاً فعلية 18% (أعلى من المتوقع 15%). Admin "خالد" يوزع الأرباح على المستثمرين البالغ عددهم 25 مستثمراً.

1. **إنهاء الصفقة** — Admin يدخل profit_actual
2. **حساب الأرباح** — كل مستثمر يحصل على حصته حسب استثماره
3. **توزيع تلقائي** — DB::transaction تضمن إضافة الأرباح لكل المحافظ
4. **إشعارات** — كل مستثمر يتلقى إشعاراً بالأرباح

## سيناريو المستخدم (User Story)

```
بصفتي: Admin في منصة Beza
أريد: إنهاء الصفقة وتوزيع الأرباح على المستثمرين
لكي: يحصل كل مستثمر على حصته من الأرباح
```

## قبول السيناريو (Acceptance Criteria)

| # | الشرط | الحالة |
|---|-------|--------|
| 1 | Admin يسجل الدخول | إجباري |
| 2 | Admin يدخل profit_actual | إجباري (نسبة مئوية) |
| 3 | حساب حصة كل مستثمر | تلقائي |
| 4 | إضافة رصيد لكل مستثمر | DB::transaction |
| 5 | تسجيل معاملات investment_profit | audit |
| 6 | تغيير حالة الصفقة إلى completed | atomic |
| 7 | إرسال إشعار لكل مستثمر | notification |

## لماذا التوزيع التلقائي؟

1. **دقة مطلقة**: حساب كل سنت بدقة
2. **سرعة**: توزيع على 100+ مستثمر في ثوانٍ
3. **شفافية**: كل مستثمر يرى حصته بالضبط

## تدفق الشاشات (User Flow)

```
[لوحة Admin] → [إتمام صفقة] → [إدخال profit_actual] → [معاينة التوزيع] → [تأكيد]
```
