# 01 - فكرة العمل - الفواتير المتكررة (Recurring)

## الفكرة الأساسية
نظام الفواتير المتكررة يسمح للتاجر بإنشاء اشتراكات دورية للعملاء يتم تحصيل قيمتها تلقائياً كل شهر أو سنة. يناسب هذا النموذج أعمال مثل: خدمة الإنترنت الشهري، اشتراكات النوادي الصحية، التأمين الصحي، خدمات SaaS، منصات البث، وصناديق الاشتراك الشهرية.

## سيناريو المستخدم الكامل
```
بصفتي: تاجر على منصة Beza
أريد: إنشاء اشتراكات متكررة للعملاء مع خصم تلقائي شهري
لكي: أحصل على مدفوعات دورية منتظمة دون تدخل يدوي
```

### خطوات السيناريو الكامل:
| الخطوة | الوصف | المسؤول |
|--------|-------|---------|
| 1 | التاجر ينشئ فاتورة متكررة للعميل (المبلغ، العملة، الدورة، الحد الأقصى للدورات) | التاجر |
| 2 | إرسال رابط موافقة للعميل عبر SMS أو WhatsApp أو البريد الإلكتروني | النظام |
| 3 | العميل يوافق على الاشتراك ويؤكد تفويض الخصم التلقائي | العميل |
| 4 | قبل الخصم بـ 3 أيام، إشعار للعميل بالمبلغ وتاريخ الخصم | النظام |
| 5 | يوم الاستحقاق، خصم تلقائي من محفظة العميل وتحويله لمحفظة التاجر | النظام |
| 6 | إرسال إيصال للطرفين بعد إتمام الدفع | النظام |
| 7 | تكرار الخطوات 4-6 حسب الدورة المحددة (شهرية/سنوية) | النظام |

## أنواع الاشتراكات المتكررة

### 1. مبلغ ثابت (Fixed Amount)
```php
// إنشاء اشتراك بمبلغ ثابت شهري
$subscription = MerchantSubscription::create([
    'merchant_id'      => $merchant->id,
    'customer_phone'   => '+963933123456',
    'amount'           => 150.00,        // 150 USD شهرياً
    'currency'         => 'USD',
    'interval'         => 'monthly',     // شهري
    'max_cycles'       => 12,            // سنة كاملة
    'description'      => 'اشتراك إنترنت 100 ميجابت - شهري',
]);
```

### 2. مبلغ متغير (Variable Amount)
```php
// اشتراك بمبلغ يختلف حسب الاستهلاك (مثل: فاتورة كهرباء)
$subscription = MerchantSubscription::create([
    'merchant_id'      => $merchant->id,
    'customer_phone'   => '+963933123456',
    'amount'           => null,          // يحسب وقت الفوترة
    'currency'         => 'SYP',
    'interval'         => 'monthly',
    'variable'         => true,
    'formula'          => 'usage_kwh * 250', // سعر الكيلوواط
    'max_cycles'       => null,          // غير محدد
]);
```

### 3. حسب الاستخدام (Usage-Based)
```php
// اشتراك يعتمد على استهلاك الخدمة (مثل: سحابة، تخزين)
$subscription = MerchantSubscription::create([
    'merchant_id'      => $merchant->id,
    'customer_phone'   => '+963933123456',
    'base_amount'      => 50.00,         // رسوم أساسية
    'currency'         => 'USD',
    'interval'         => 'monthly',
    'usage_based'      => true,
    'per_unit'         => 0.50,          // 0.50 لكل GB
    'billing_period'   => 'last_month',  // احتساب استهلاك الشهر الماضي
]);
```

## القيمة التجارية للتاجر

| الفائدة | الشرح |
|---------|-------|
| **إيرادات متوقعة** | تدفق نقدي منتظم يمكن التخطيط بناءً عليه |
| **تقليل تراجع العملاء** | الاشتراك التلقائي يقلل الاحتكاك والانسحاب |
| **أتمتة كاملة** | لا حاجة لإرسال فواتير يدوية أو متابعة تحصيل |
| **ولاء العملاء** | العملاء يفضلون الدفع التلقائي عن إعادة الدفع كل مرة |
| **توسع الأعمال** | سهولة إدارة آلاف الاشتراكات دون زيادة في الجهد |

## شروط القبول (Acceptance Criteria)

| # | الشرط | معيار النجاح |
|---|-------|-------------|
| 1 | إنشاء اشتراك (customer_phone, amount, currency, interval) | يتم إنشاء الاشتراك بحالة `pending` |
| 2 | موافقة العميل على الاشتراك | تحديث الحالة إلى `active` مع تسجيل وقت الموافقة |
| 3 | خصم تلقائي في كل دورة | معالجة الدفع بدون تدخل يدوي بنسبة نجاح ≥ 99% |
| 4 | إشعار قبل الخصم بـ 3 أيام | وصول الإشعار عبر FCM وSMS والبريد |
| 5 | تحديد max_cycles | إيقاف الاشتراك تلقائياً عند الوصول للحد الأقصى |
| 6 | معالجة حالات فشل الدفع | إعادة محاولة 3 مرات مع تباعد زمني |
| 7 | إلغاء الاشتراك من العميل | تحديث الحالة إلى `cancelled` ووقف الخصم فوراً |
| 8 | تغيير المبلغ في الدورة التالية | يمكن فقط بإنشاء اشتراك جديد |
