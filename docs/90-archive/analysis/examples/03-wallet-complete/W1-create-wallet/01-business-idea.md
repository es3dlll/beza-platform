# 01 - فكرة العمل وسيناريو المستخدم (Business Idea & User Scenario)

## الفكرة الأساسية

عندما يسجل مستخدم جديد في Beza، يحتاج فوراً إلى محفظة رقمية لبدء استخدام المنصة. بدلاً من أن يطلب المستخدم إنشاء محفظة يدوياً، يقوم النظام تلقائياً بإنشاء محفظتين له:

1. **محفظة SYP** (ل.س) — العملة المحلية
2. **محفظة USD** (دولار) — العملة الأجنبية

ويحصل المستخدم على **هدية 5 دولار** في محفظة USD ليشجع على البدء باستخدام المنصة.

## سيناريو المستخدم (User Story)

```
بصفتي: مستخدم جديد في Beza
أريد: الحصول على محفظتين (SYP + USD) تلقائياً عند التسجيل
لكي: أبدأ باستخدام المنصة فوراً دون الحاجة لإنشاء محفظة يدوياً
```

## قبول السيناريو (Acceptance Criteria)

| # | الشرط | الحالة |
|---|-------|--------|
| 1 | عند تسجيل مستخدم جديد، يتم إنشاء محفظة SYP برصيد 0 | تلقائي |
| 2 | عند تسجيل مستخدم جديد، يتم إنشاء محفظة USD برصيد 5 | تلقائي |
| 3 | كل محفظة لها رقم محفظة فريد (wallet_number) | إجباري |
| 4 | بادئة رقم محفظة SYP: 62 | تنسيق |
| 5 | بادئة رقم محفظة USD: 63 | تنسيق |
| 6 | لا يمكن أن يملك المستخدم محفظتين بنفس العملة | business rule |
| 7 | لا يمكن إنشاء محفظة لمستخدم غير نشط | business rule |
| 8 | يتم تسجيل هدية 5 USD كمعاملة من نوع 'deposit' | audit |
| 9 | إرسال إشعار ترحيبي للمستخدم الجديد | notification |
| 10 | عرض المحفظتين في الشاشة الرئيسية بعد التسجيل | UX |

## لماذا هدية 5$؟

1. **تحفيز التسجيل**: المستخدم يشعر بقيمة فورية
2. **تجربة أولى مجانية**: يشجع على تجربة التحويل والصرافة
3. **نمو المنصة**: كل مستخدم جديد يزيد من قيمة الشبكة

## تدفق الشاشات (User Flow)

```
[تسجيل الدخول] → [تعبئة البيانات] → [تأكيد] → [إنشاء المحافظ تلقائياً] → [الرئيسية]
                                                                ↓
                                                    [إشعار ترحيبي + هدية 5$]
```
