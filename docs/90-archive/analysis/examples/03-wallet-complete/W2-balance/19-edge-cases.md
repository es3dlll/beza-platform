# 19 - حالات الحافة + سيناريوهات خطأ (Edge Cases)

## 1. مستخدم بدون محافظ (نادر)

**المشكلة**: مستخدم مسجل لكن ليس لديه محافظ (خطأ في W1).

**الحل**: التحقق من وجود المحافظ وإرجاع 404.

## 2. خادم Cache (Redis) معطل

**المشكلة**: Redis Down → كل الطلبات تذهب إلى MySQL.

**الحل**: Try-catch حول Cache → Fallback إلى DB.

```php
try {
    $cached = Cache::get($cacheKey);
    if ($cached !== null) return $cached;
} catch (\Throwable $e) {
    Log::warning('Redis unavailable');
}
// Fallback to DB
```

## 3. Cache قديم (Stale Cache)

**المشكلة**: معاملة تغيّر الرصيد لكن Cache لم يُمسح.

**الحل**: TTL 30 ثانية فقط + مسح Cache في كل عملية تغيير رصيد.

## 4. محفظة واحدة فقط (مفقودة الثانية)

**المشكلة**: مستخدم لديه SYP فقط (USD مفقودة).

**الحل**: إرجاع null للعملة المفقودة بدلاً من خطأ.

```json
{
    "syp": { "balance": 1000, ... },
    "usd": null
}
```

## 5. رصيد كبير جداً

**المشكلة**: رصيد يتجاوز DECIMAL(15,2) = 9999999999999.99.

**الحل**: إرجاع القيمة كما هي مع تنسيق JSON رقمي.

## 6. محفظة موقوفة (is_active = false)

**المشكلة**: المحفظة موقوفة لكن المستخدم يطلب الرصيد.

**الحل**: إرجاع الرصيد مع إشارة إلى أن المحفظة موقوفة. أو استثناء.

## 7. تزامن Cache مع DB (Race Condition)

**المشكلة**: طلبين متزامنين — أحدهما يقرأ Cache والآخر يمسحه.

**الحل**: TTL قصير (30 ثانية) + مسح Cache قبل/بعد الكتابة.

## 8. تجاوز Rate Limit

**المشكلة**: 60 طلب/دقيقة → 429 Too Many Requests.

**الحل**: Increase limit للرصيد لأنه READ فقط.

## 9. مهلة Cache طويلة جداً

**المشكلة**: TTL = 5 دقائق → المستخدم يرى رصيد قديماً.

**الحل**: TTL = 30 ثانية — توازن بين الأداء والدقة.

## 10. محفظة برصيد سالب (خطأ في DB)

**المشكلة**: خطأ برمجي أدى إلى رصيد سالب.

**الحل**: إرجاع الرصيد كما هو مع تسجيل خطأ. لا يمكن إخفاءه.

## 11. تنسيق العملة (SYP ليس لديه كسور)

**المشكلة**: عرض 0.00 SYP لا معنى له (SYP ليس لديه كسور).

**الحل**: عرض SYP بدون كسور في الـ UI.

## 12. مستخدم محذوف (Soft Delete)

**المشكلة**: مستخدم محذوف لكن المحفظة موجودة.

**الحل**: Middleware يمنع وصول المحذوفين → 401.

## جدول ملخص حالات الحافة

| # | الحالة | النتيجة | مستوى المعالجة |

| 5 | رصيد كبير جداً | JSON Number | DB + Serialization |
| 6 | محفظة موقوفة | عرض مع تنبيه | Application |
