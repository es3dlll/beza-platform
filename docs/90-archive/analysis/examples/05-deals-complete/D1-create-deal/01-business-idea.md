# 01 - فكرة العمل وسيناريو المستخدم (Business Idea & User Scenario)

## الفكرة الأساسية

مدير منصة Beza "خالد" يريد إنشاء صفقة استثمارية جديدة في مجال تجارة الشحنات. الهدف: جمع 50,000 USD من المستثمرين لتمويل شحنة، مع أرباح متوقعة 15% خلال 90 يوماً.

1. **إدارة الصفقات** — Admin ينشئ ويدير الصفقات الاستثمارية
2. **جمع رأس المال** — target_amount يحدد الهدف
3. **نظام مراجعة** — pending → مراجعة → active
4. **عرض للمستثمرين** — الصفقة النشطة تظهر للمستثمرين

## سيناريو المستخدم (User Story)

```
بصفتي: Admin في منصة Beza
أريد: إنشاء صفقة استثمارية جديدة
لكي: يتمكن المستثمرون من المشاركة فيها وتحقيق الأرباح
```

## قبول السيناريو (Acceptance Criteria)

| # | الشرط | الحالة |
|---|-------|--------|
| 1 | Admin يسجل الدخول | إجباري |
| 2 | Admin يملأ title, description, target_amount | إجباري |
| 3 | Admin يختار العملة (SYP/USD) | إجباري |
| 4 | Admin يدخل expected_profit_percentage | إجباري |
| 5 | Admin يدخل duration_days | إجباري |
| 6 | Admin يختار category (تجارة/شحنات/...) | إجباري |
| 7 | Admin يحدد risk_level (منخفض/متوسط/مرتفع) | إجباري |
| 8 | التحقق من أن target_amount ≥ 100 USD | validation |
| 9 | التحقق من expected_profit بين 1%-100% | validation |
| 10 | الحالة الأولية pending | business rule |
| 11 | تسجيل الصفقة في جدول deals | audit |
| 12 | إرسال إشعار للمشرفين للمراجعة | notification |

## لماذا يحتاج Admin إلى إنشاء الصفقات؟

1. **توسيع قاعدة الاستثمارات**: تنويع الفرص الاستثمارية
2. **الشفافية**: المستثمرون يرون تفاصيل كاملة عن كل صفقة
3. **الرقابة**: كل صفقة تمر بمرحلة مراجعة قبل النشر

## تدفق الشاشات (User Flow)

```
[لوحة Admin] → [إنشاء صفقة] → [ملء البيانات] → [معاينة] → [حفظ (pending)]
                                                                    ↓
                                                          [مراجعة → active]
```
