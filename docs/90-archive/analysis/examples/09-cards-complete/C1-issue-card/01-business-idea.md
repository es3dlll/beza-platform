# 01 - فكرة المشروع - إصدار البطاقة (Issue Card)

## الفكرة الأساسية
تمكين مستخدمي Beza من إصدار بطاقات دفع (debit card) افتراضية أو فيزيائية مرتبطة بمحفظتهم الرقمية للدفع عبر الإنترنت وفي المتاجر دون الحاجة لاستخدام المحفظة مباشرة.

## سيناريو المستخدم
```
بصفتي: مستخدم Beza
أريد: إصدار بطاقة دفع افتراضية أو فيزيائية
لكي: أتمكن من الشراء أونلاين وفي المتاجر دون كشف بيانات محفظتي
```

## تدفق المستخدم (User Flow)
```
┌──────────┐    ┌──────────────┐    ┌────────────────┐    ┌─────────────┐
│  Cards   │───▶│  اختيار      │───▶│  تحديد الحد    │───▶│  مراجعة     │
│  Section │    │  Virtual/    │    │  اليومي        │    │  والتأكيد   │
│          │    │  Physical    │    │  (اختياري)     │    │             │
└──────────┘    └──────────────┘    └────────────────┘    └──────┬──────┘
                                                                 │
                                                                 ▼
                                                  ┌──────────────────────────┐
                                                  │ Virtual → تصدر فوراً     │
                                                  │ Physical → تطلب للتوصيل │
                                                  └──────────────────────────┘
```

## قبول السيناريو (Acceptance Criteria)
| # | الشرط | الحالة |
|---|-------|--------|
| 1 | اختيار نوع البطاقة (Virtual/Physical) | إجباري |
| 2 | اختيار العملة (SYP/USD) | إجباري |
| 3 | تحديد الحد اليومي (daily_limit) | اختياري |
| 4 | إدخال عنوان الشحن (للبطاقة الفيزيائية) | إجباري للفيزيائية |
| 5 | إصدار البطاقة الافتراضية فوراً بحالة active | تلقائي |
| 6 | إظهار PAN و expiry و CVV للبطاقة الافتراضية | تلقائي |
| 7 | البطاقة الفيزيائية بحالة pending لحين التوصيل | تلقائي |
| 8 | إخفاء PAN مع إظهار آخر 4 أرقام فقط | أمني |
| 9 | ربط البطاقة بمحفظة المستخدم الرئيسية | تلقائي |
| 10 | منع إصدار أكثر من بطاقة افتراضية واحدة نشطة | منطق الأعمال |
