# دليل تكامل QR في نقاط البيع (POS)

## الغرض

يساعد هذا الدليل مطوري المتاجر الفعلية على دمج نظام الدفع عبر رمز QR في نقاط البيع الخاصة بهم (شاشة عرض أو طابعة إيصالات). الدليل مبني على مواصفات M7 و MERCHANT-API-SPEC.

---

## مرحلة الإعداد (Setup)

### المتطلبات الأساسية

| العنصر | الوصف |
|--------|-------|
| حساب تاجر | حساب نشط ومعتمد على منصة Beza |
| مفتاح API | مفتاح API سري (32 بايت) من لوحة التحكم |
| Bearer Token | توكن مصادقة للتاجر (يُحصل عليه عبر `/auth/login`) |
| بيئة التشغيل | متصفح (مع QR على الشاشة) أو طابعة إيصالات حرارية |
| اتصال إنترنت | مطلوب للتوليد والتحقق — يُمكن العمل بـ offline fallback |

### الحصول على المفتاح السري

```
1. سجّل الدخول إلى لوحة تحكم التاجر
2. انتقل إلى Settings > API Keys
3. أنشئ مفتاحاً جديداً مع صلاحية read+write
4. احفظ المفتاح في مكان آمن (لن يظهر مجدداً)
```

## مرحلة التشغيل اليومي

### سيناريو 1: QR ديناميكي على شاشة العرض (مبلغ متغير)

مناسب للمتاجر التي يُحدد فيها المبلغ عند كل عملية شراء (سوبرماركت، مطعم، ملابس).

```
1. أمين الصندوق يُدخل المبلغ في نظام نقاط البيع
2. نظام POS يستدعي POST /api/v1/merchant/qr/generate
3. الخادم يُعيد: QR على هيئة base64 PNG + SVG + JSON
4. نظام POS يعرض QR على الشاشة (أو يرسله للعميل جوالاً)
5. العميل يمسح QR بتطبيق Beza
6. العميل يؤكد الدفع ← QR يُدفع
7. نظام POS يتلقى webhook "تم الدفع" ← يُغلق المعاملة
```

### سيناريو 2: QR ثابت للعرض (مبلغ ثابت)

مناسب للمتاجر ذات الأسعار الثابتة (مقهى، كشك، مواقف سيارات).

```
1. التاجر يُنشئ QR للمبلغ الثابت مسبقاً (مثلاً 3.00 USD)
2. يطبع QR ويضعه على الطاولة أو الشباك
3. العميل يمسح QR ويدفع المبلغ المحدد
4. QR يُستخدم مرة واحدة (transaction_id فريد لكل طباعة)
5. بعد الدفع، QR لم يعد صالحاً
```

ملاحظة: QR الثابت يُنشأ لمرة واحدة فقط لكل معاملة. لا يُعيد استخدام QR مدفوع مسبقاً.

### سيناريو 3: QR للطباعة على الإيصال

مناسب للمتاجر التي تطبع إيصالات ورقية.

```
1. أمين الصندوق يُدخل المبلغ
2. POST /qr/generate ← يحصل على QR SVG
3. يطبع QR SVG على الإيصال الحراري
4. العميل يمسح QR من الإيصال
5. QR صالح لمدة 15 دقيقة من الطباعة
```

## دليل البدء السريع (كود)

### توليد QR (طلب)

```bash
curl -X POST https://api.beza.com/api/v1/merchant/qr/generate \
  -H "Authorization: Bearer eyJ0eXAiOiJKV1QiLCJhbGciOiJIUzI1NiJ9..." \
  -H "Content-Type: application/json" \
  -d '{
    "amount": 2500,
    "currency": "USD",
    "description": "قهوة أمريكانو + سندويش",
    "branch_id": "BR-01"
  }'
```

### التحقق من QR (طلب)

```bash
curl -X POST https://api.beza.com/api/v1/merchant/qr/verify \
  -H "Authorization: Bearer eyJ0eXAiOiJKV1QiLCJhbGciOiJIUzI1NiJ9..." \
  -H "Content-Type: application/json" \
  -d '{
    "qr_data": "{\"v\":1,\"mid\":\"merch_a1b2\",\"tid\":\"txn_f6e7d8\",\"a\":2500,\"c\":\"USD\",\"e\":\"20260531T141500Z\",\"s\":\"a1b2c3d4...\"}"
  }'
```

## حالات الطوارئ (Emergency Scenarios)

### الدفع بدون اتصال (Offline)

إذا انقطع الإنترنت لدى التاجر:
1. يُظهر رمز QR مولّد سابقاً (لا يزال ساري المفعول)
2. العميل يمسح بدفعته (جوال العميل متصل بالإنترنت)
3. إذا تعذر التحقق، يُخزّن الطلب في قائمة انتظار
4. عند عودة الاتصال، تُرسَل الدفعات المعلقة

### محاولة دفع مزدوجة

1. العميل يمسح QR نفسه مرتين
2. المرة الثانية ← `QR_ALREADY_PAID`
3. التطبيق يعرض "تم دفع هذا الرمز مسبقاً"
4. التجربة: يُظهر للتاجر آخر معاملة ناجحة

### QR قديم معروض على الطاولة

1. QR مطبوع على طاولة استخدم سابقاً
2. QR الأصلي يحمل transaction_id فريد تم دفعه سابقاً
3. أي مسح جديد ← `QR_ALREADY_PAID`
4. الحل: يطلب التاجر من الزبون إعلامه لطباعة QR جديد

## خريطة التكامل الكاملة

```
+-----------+          +-------------+          +-------------+
| POS       | ---HTTP->| Beza API    | ---DB--->| MySQL       |
| (شاشة عرض)| <--JSON- | (QR Service)| <--DB--- | (merchant_) |
| طابعة     |          | Auth Guard  |          | (qr_codes)  |
+-----------+          +------+------+          | (wallets)   |
                              |                  +-------------+
                              | Webhook
                              v
                        +-----------+
                        | Webhook   |
                        | تاجر/POS  |
                        +-----------+
```
