# 01 - فكرة العمل وسيناريو المستخدم (Business Idea) — رمز التحقق (OTP)

## الفكرة الأساسية

المستخدم "علي" سجل حديثاً في Beza ويحتاج لتأكيد رقم هاتفه عبر OTP. العملية:
1. **طلب OTP** — إرسال رمز 6 أرقام عبر SMS
2. **التحقق** — إدخال الرمز لتأكيد ملكية الرقم
3. **صلاحية محدودة** — 5 دقائق فقط
4. **إلغاء الرمز السابق** — كل طلب جديد يلغي القديم

## سيناريو المستخدم (User Story)

```
بصفتي: مستخدم جديد في Beza
أريد: تأكيد رقم هاتفي عبر رمز التحقق
لكي: أتمكن من تفعيل حسابي واستخدام الخدمات
```

## قبول السيناريو (Acceptance Criteria)

| # | الشرط | الحالة |
|---|-------|--------|
| 1 | طلب OTP عبر إدخال رقم الهاتف | إجباري |
| 2 | توليد 6 أرقام عشوائية آمنة | OK |
| 3 | تخزين OTP في Redis مع expiry 300s | OK |
| 4 | إرسال OTP عبر SMS | OK |
| 5 | في بيئة التطوير — إرجاع OTP في الاستجابة | OK |
| 6 | إدخال OTP للتحقق | إجباري |
| 7 | مقارنة OTP مع Cache | OK |
| 8 | تحديث phone_verified_at | OK |
| 9 | كل طلب جديد يلغي الرمز القديم | OK |
| 10 | OTP منتهي الصلاحية → رفض | OK |

## تدفق الشاشات (User Flow)

```
[تسجيل] → [طلب OTP] → [إدخال الرمز] → [تأكيد] → [الرئيسية]
```

## لماذا Redis بدلاً من DB؟

1. **سرعة** — Cache أسرع بكثير من MySQL
2. **انتهاء تلقائي** — TTL يحذف الرمز بعد 5 دقائق
3. **لا حاجة لجدول** — OTPs مؤقتة لا تحتاج تخزين دائم
