# 01 - فكرة العمل وسيناريو المستخدم (Business Idea & User Scenario)

## الفكرة الأساسية
تمكين الوكلاء من طلب تسوية (settlement) لأرباحهم وعمولاتهم المتراكمة إلى حساباتهم البنكية، مع عملية موافقة من الإدارة.

## سيناريو المستخدم
```
بصفتي: وكيل Beza
أريد: سحب أرباحي المتراكمة إلى حسابي البنكي
لكي: أتمكن من تحويل عمولاتي إلى نقد
```

## تدفق المستخدم (User Flow)
```
┌──────────────┐    ┌────────────────┐    ┌────────────────┐
│  الوكيل يدخل │───▶│  اختيار الحساب │───▶│  تأكيد الطلب   │
│  المبلغ      │    │  البنكي        │    │  (Pending)     │
└──────────────┘    └────────────────┘    └───────┬────────┘
                                                   │
                                                   ▼
                                        ┌────────────────────┐
                                        │  Admin يراجع الطلب  │
                                        │  ┌──────┐ ┌──────┐ │
                                        │  │موافقة│ │ رفض  │ │
                                        │  └──────┘ └──────┘ │
                                        └────────┬───────────┘
                                                 │
                          ┌──────────────────────┴──────────────┐
                          ▼                                     ▼
                  ┌──────────────┐                     ┌──────────────┐
                  │ Approved     │                     │  Rejected    │
                  │ ← تحويل      │                     │  ← مع سبب    │
                  │ إلى الحساب   │                     │  الرفض      │
                  └──────────────┘                     └──────────────┘
```

## قبول السيناريو (Acceptance Criteria)
| # | الشرط | الحالة |
|---|-------|--------|
| 1 | إدخال المبلغ المطلوب تسويته (amount) | إجباري |
| 2 | اختيار الحساب البنكي (bank_account_id) | إجباري |
| 3 | التحقق من أن المبلغ لا يتجاوز الرصيد المتاح | إجباري |
| 4 | التحقق من الحد الأدنى للتسوية (minimum) | إجباري |
| 5 | إنشاء طلب تسوية بحالة pending | تلقائي |
| 6 | مراجعة الطلب من Admin (موافقة/رفض) | يدوي |
| 7 | إلغاء الطلب من قبل الوكيل قبل الموافقة | إجباري |
| 8 | منع إلغاء الطلب بعد الموافقة | منطق الأعمال |
| 9 | حساب الرسوم (fee) عند الموافقة | تلقائي |
| 10 | إشعار الوكيل بتغير حالة الطلب | إعلامي |
