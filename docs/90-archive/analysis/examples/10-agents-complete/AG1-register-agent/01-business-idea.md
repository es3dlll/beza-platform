# 01 - فكرة العمل وسيناريو المستخدم (Business Idea & User Scenario)

## الفكرة الأساسية
تمكين مستخدمي Beza من التسجيل كوكلاء (agents) معتمدين لتقديم خدمات مالية مثل الإيداع والسحب للعملاء، مع التحقق من الهوية من قبل الإدارة.

## سيناريو المستخدم
```
بصفتي: مستخدم Beza
أريد: التسجيل كموزع معتمد في المنصة
لكي: أتمكن من تقديم خدمات مالية للعملاء وكسب عمولات
```

## تدفق المستخدم (User Flow)
```
┌──────────┐    ┌────────────────┐    ┌──────────────┐    ┌──────────────┐
│  Register│───▶│  إدخال البيانات│───▶│  رفع صورة    │───▶│  تقديم الطلب │
│  Agent   │    │  الشخصية       │    │  الهوية      │    │  (Pending)   │
└──────────┘    └────────────────┘    └──────────────┘    └──────┬───────┘
                                                                 │
                                                                 ▼
                                                      ┌──────────────────┐
                                                      │  Admin يراجع     │
                                                      │  ويوافق/يرفض    │
                                                      └────────┬─────────┘
                                                               │
                                           ┌───────────────────┴────────────┐
                                           ▼                              ▼
                                    ┌──────────────┐             ┌──────────────┐
                                    │ Approved      │             │ Rejected     │
                                    │ ← تفعيل وكيل  │             │ ← سبب الرفض  │
                                    └──────────────┘             └──────────────┘
```

## قبول السيناريو (Acceptance Criteria)
| # | الشرط | الحالة |
|---|-------|--------|
| 1 | إدخال الاسم الكامل (full_name) | إجباري |
| 2 | إدخال رقم الهاتف (phone) | إجباري |
| 3 | إدخال رقم الهوية (id_number) | إجباري |
| 4 | رفع صورة الهوية (id_photo) | إجباري |
| 5 | إدخال الموقع (location_lat/lng) | اختياري |
| 6 | إنشاء طلب وكيل بحالة pending | تلقائي |
| 7 | منع تسجيل مستخدم كوكيل مسبقاً | منطق الأعمال |
| 8 | التحقق من رقم الهاتف الفريد | تحقق |
| 9 | مراجعة يدوية من Admin للموافقة/الرفض | يدوي |
| 10 | إشعار المستخدم بنتيجة الطلب | إعلامي |
