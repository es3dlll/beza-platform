## 2. المصادقة (Authentication) - 02-auth-complete

**عدد العمليات:** 5 | **الأولوية:** P0-P1

### 2.1 العمليات

| المعرف | العملية | الأولوية | طريقة التنفيذ |
|--------|---------|----------|---------------|
| A1 | تسجيل مستخدم جديد | P0 | رقم الهاتف ← OTP ← إنشاء PIN |
| A2 | تسجيل الدخول | P0 | رقم الهاتف + PIN (أو OTP) |
| A3 | طلب والتحقق من OTP | P0 | SMS عبر Twilio، صلاحية 5 دقائق |
| A4 | تسجيل الخروج | P0 | إبطال Sanctum token |
| A5 | المصادقة الثنائية (2FA) | P1 | TOTP (Google Authenticator) |

### 2.2 سيناريو الاستخدام

```
[1] مستخدم يفتح التطبيق ← شاشة الترحيب
[2] يدخل رقم الهاتف ← "أرسل رمز التحقق"
[3] OTP يصل عبر SMS ← يدخل الرمز ← يُصدق
[4] يُطلب إنشاء PIN (4-6 أرقام)
[5] يُنشأ حساب + محفظتان (SYP/USD)
[6] يُصدر Sanctum token ← يُحفظ في التطبيق
[7] للمبالغ > 1000$: يُطلب تفعيل 2FA باستخدام Google Authenticator
```

### 2.3 الميزات التنافسية

- **ثلاث طبقات مصادقة:** PIN + OTP + 2FA (TOTP)
- **قفل أمني:** بعد 5 محاولات PIN خاطئة يُقفل الحساب 30 دقيقة
- **إعادة المصادقة:** للعمليات الحساسة (تحويل > 1000$، تغيير PIN)
- **جلسات محدودة:** تنتهي بعد 30 دقيقة من الخمول
- **Sanctum tokens:** مع صلاحيات (user, merchant, agent, admin)

### 2.4 المقارنة

| الميزة | Beza | منافسون |
|--------|------|---------|
| طبقات المصادقة | PIN + OTP + 2FA | OTP فقط (معظمهم) |
| قفل الحساب | 5 محاولات | متغير |
| إعادة المصادقة | للمبالغ > 1000$ | نادر |
| إبطال التوكن | فوري عند logout | متغير |

## 3. المحفظة الرقمية (Digital Wallet) - 03-wallet-complete

**عدد العمليات:** 3 | **الأولوية:** P0

### 3.1 العمليات

| المعرف | العملية | الأولوية | الوظيفة |
|--------|---------|----------|---------|
| W1 | إنشاء المحفظة المزدوجة | P0 | تُنشأ SYP + USD تلقائياً بعد التسجيل |
| W2 | عرض الرصيد | P0 | رصيد متاح + مجمد + سجل معاملات |
| W3 | تحويل بين العملات | P0 | SYP ↔ USD بسعر صرف تنافسي |

### 3.2 سيناريو الاستخدام

```
[1] بعد تسجيل مستخدم جديد ← تُنشأ محفظتان (SYP و USD) تلقائياً
[2] W2: المستخدم يفتح الصفحة الرئيسية ← يرى رصيده بـ SYP و USD
[3] W3: يريد تحويل 500$ إلى SYP ← يدخل المبلغ ← يحصل على سعر الصرف ← يؤكد
[4] تتم عملية الصرف ← يُخصم من USD ← يُضاف SYP بسعر الصرف + هامش 0.5%
```

### 3.3 الميزات التنافسية

- **محفظة مزدوجة:** SYP + USD لكل مستخدم (فريدة في السوق السوري)
- **Frozen balance:** تجميد رصيد للصفقات الاستثمارية (يمنع السحب مرتين)
- **Atomic transactions:** جميع العمليات في DB transaction مع Pessimistic Locking
- **رقم محفظة فريد:** wallet_number فريد لكل محفظة
- **رسوم صرف:** 0.5% فقط (هامش ربح)

### 3.4 هيكل جدول المحافظ

```php
wallets: id | user_id | currency(SYP/USD) | wallet_number(unique) | balance | frozen_balance | is_active
```

## 4. التحويل P2P (Transfer) - 01-transfer-complete

**عدد العمليات:** 1 | **الأولوية:** P0

### 4.1 العملية

| المعرف | العملية | الأولوية | الوظيفة |
|--------|---------|----------|---------|
| T1 | تحويل بين المستخدمين | P0 | تحويل فوري برقم الهاتف |

### 4.2 سيناريو الاستخدام

```
[1] المرسل يفتح "تحويل" ← يدخل رقم هاتف المستلم ← المبلغ ← العملة
[2] النظام يبحث عن المستلم ← يظهر اسمه للتأكيد
[3] المرسل يدخل PIN التأكيد
[4] يحصل تحقق إضافي:
    - ليس تحويلاً للذات (self-transfer)
    - الرصيد كافٍ
    - لم يتجاوز الحد اليومي (2000$ أو 2,000,000 SYP)
[5] تبدأ المعاملة الذرية (Atomic):
    - قفل محفظة المرسل ← خصم المبلغ
    - قفل محفظة المستلم ← إضافة المبلغ
    - تسجيل المعاملة في جدول transactions
[6] يُطلق حدث TransactionCompleted ← إشعار FCM للمستلم
[7] المستلم يتلقى إشعار "استلمت 100$ من أحمد"
```

### 4.3 الميزات التنافسية

- **0% رسوم** — مجاني تماماً (أقل بكثير من PayPal 2.9% + 0.30$)
- **Pessimistic Locking** — FOR UPDATE يمنع الـ Race Conditions
- **Atomic DB Transaction** — خصم + إضافة في خطوة واحدة (لا يمكن أن تنجح واحدة وتفشل الثانية)
- **Deadlock prevention** — قفل المحافظ بترتيب ثابت (sorted IDs)
- **إشعار فوري** — FCM للمستلم فور إتمام التحويل

### 4.4 هيكل جدول المعاملات

```php
transactions: id | from_wallet_id | to_wallet_id | amount | amount_in_usd |
               type(transfer/exchange/deposit/withdraw/payment) |
               status(pending/completed/failed/refunded) |
               reference_number(unique) | fee | metadata(JSON) | completed_at
```

### 4.5 المقارنة

| الميزة | Beza | PayPal | Venmo | CashApp |
|--------|------|--------|-------|---------|
| رسوم P2P | **0%** | 2.9% + 0.30$ | 0% (بطاقة 3%) | 0% (بطاقة 3%) |
| فوري | نعم | نعم | نعم | نعم |
| رقم هاتف | نعم | بريد إلكتروني | اسم مستخدم | اسم مستخدم |
| حد يومي | 2000$ / 2M SYP | 10,000$ | 3,000$ | 7,500$ |
| PIN + 2FA | نعم | كلمة مرور فقط | PIN فقط | كلمة مرور |

## 6. الصفقات الاستثمارية (Deals) - 05-deals-complete

**عدد العمليات:** 4 | **الأولوية:** P1

### 6.1 العمليات

| المعرف | العملية | الأولوية | الوظيفة |
|--------|---------|----------|---------|
| D1 | إنشاء صفقة (Admin) | P1 | المشرف ينشئ صفقة تمويل شحنة تجارية |
| D2 | المشاركة في صفقة | P1 | المستخدم يساهم بمبلغ من محفظته |
| D3 | إتمام الصفقة + توزيع الأرباح | P1 | تلقائي بعد بيع الشحنة |
| D4 | إلغاء صفقة + استرجاع | P1 | في حالة فشل الصفقة |

### 6.2 سيناريو الاستخدام

```
[1] فريق الإدارة يجد فرصة: شحنة إلكترونيات من دبي إلى دمشق بقيمة 50,000$
[2] ينشئ صفقة: المبلغ المستهدف 50k$، المدة 45 يوماً، الربح المتوقع 8%
[3] المستخدمون يشاهدون الصفقة في التطبيق ← يقرؤون التفاصيل ← المخاطرة ← المدة
[4] خالد يساهم بـ 500$ ← تُجمد من محفظته ← يُسجل في deal_investments
[5] ليلى تساهم بـ 1,000$ ← تُجمد من محفظتها
[6] بعد 45 يوماً: تُباع الشحنة ← ربح 4,000$ (8%)
[7] D3: تُوزع الأرباح تلقائياً:
    - خالد: 500$ + (500/50000 × 4000) = 500 + 40 = 540$
    - ليلى: 1,000$ + (1000/50000 × 4000) = 1,000 + 80 = 1,080$
[8] يُفك التجميد ← يُضاف إلى المحافظ ← إشعار للمستثمرين
```

### 6.3 الميزات التنافسية

- **تمويل تجاري فعلي:** كل صفقة لها شحنة ووثائق (وليس Crypto أو Fixed Interest)
- **متوافق مع الشريعة:** لا فوائد ربوية، لا رافعة مالية، غنم بغرم
- **ربح محدد مسبقاً:** المستخدم يعرف الربح قبل المشاركة
- **توزيع تلقائي:** عقود ذكية على مستوى التطبيق
- **شفاف:** سجل كامل لكل صفقة من إنشائها حتى توزيع الأرباح

## 7. الذهب والفضة (Gold & Silver) - 18-gold-silver-complete

**عدد العمليات:** 1 (G1) | **الأولوية:** P1

### 7.1 العملية

| المعرف | العملية | الأولوية | الوظيفة |
|--------|---------|----------|---------|
| G1 | شراء وبيع الذهب والفضة | P1 | شراء/بيع بالجرامات، تخزين في خزائن فعلية |

### 7.2 سيناريو الاستخدام

```
[1] المستخدم يفتح "الذهب والفضة" ← يرى سعر XAU/USD و XAG/USD لحظياً
[2] يشتري 0.5 جرام ذهب ← سعر السوق 3,000$ + هامش 1.5% = 3,045$
[3] يُخصم من محفظة USD ← يُسجل في commodity_holdings: 0.5 جرام
[4] يُخزن الذهب فعلياً في خزينة شركة حراسة (طرف ثالث)
[5] بعد شهر: سعر الذهب يرتفع إلى 3,100$
[6] يبيع 0.25 جرام ← يُضاف إلى محفظته 775$ (بعد خصم هامش)
[7] يستطيع متابعة قيمة محفظته الذهبية لحظياً في التطبيق
```

### 7.3 الميزات التنافسية

- **ادخار عيني:** تملك ذهباً فعلياً (وليس CFD أو ورقة مالية)
- **تخزين آمن:** في خزائن شركة حراسة بتأمين كامل
- **سيولة عالية:** بيع في أي وقت بسعر السوق
- **بدون رافعة مالية:** تشتري ما تملك فقط (متوافق مع الشريعة)
- **هامش شفاف:** 1-2% فقط (أقل من محلات الذهب 5-10%)
- **حد أدنى منخفض:** 0.1 جرام ذهب / 1 جرام فضة

### 7.4 هيكل جدول الذهب

```php
commodity_holdings: id | user_id | type(gold/silver) | grams(decimal) |
```

## 14. نقاط القوة والضعف (SWOT Analysis)

### 14.1 نقاط القوة (Strengths)

| النقطة | الشرح |
|--------|-------|

| **P2P مجاني (0%)** | أداة جذب قوية جداً. PayPal يفرض 2.9% + 0.30$. الفرق = المستخدم يفضل Beza للتحويلات |
| **Sharia-compliant** | في سوق عربي ومسلم، التوافق مع الشريعة ميزة تنافسية هائلة. الاستثمار في تجارة حقيقية (وليس فوائد)، والذهب عيني (وليس تداول) |
| **شبكة وكلاء** | تحل مشكلة الشمول المالي (47% من السوريين بلا حسابات بنكية). الوكيل = ATM بشري |
| **توثيق شامل جداً** | 1,172 ملف تغطي كل سيناريو، كل Edge Case، وكل Security Audit — هذا يخفض وقت التطوير لاحقاً بشكل كبير |
| **محفظة مزدوجة SYP/USD** | فريدة في السوق السوري. تحل مشكلة تذبذب العملة المحلية |
| **دعم محلي كامل** | RTL عربي، بنوك محلية، عملة محلية، دعم فني بالعربية |

### 14.2 نقاط الضعف (Weaknesses)

| النقطة | الشرح | التأثير |
|--------|-------|---------|
| **اعتماد على خدمات خارجية** | Shufti Pro (KYC), Stripe (بطاقات), Twilio (SMS), Google Maps | عالي — لو أي خدمة توقفت أو حُظرت في سوريا، تتأثر المنصة |
| **تعقيد تقني** | 5 واجهات (React ×2, Flutter, Next.js, Admin) + Laravel + MySQL + Redis | صيانة مكلفة، تحتاج فريق متعدد التخصصات |
| **MySQL فقط** | حالياً localhost. التوسع الأفقي (sharding/replication) غير مطبق | مشكلة أداء عند 100k+ مستخدم |
| **الاستثمار في الصفقات** | يعتمد على إدارة فعالة لتقييم مخاطر الشحنات التجارية | مخاطرة تشغيلية — خسارة صفقة = فقدان ثقة المستثمرين |
| **الذهب العيني** | يتطلب خزائن فعلية، شركة حراسة، تأمين، شحن | تكلفة تشغيل عالية، تعقيد لوجستي |
| **Sanctum على localhost** | غير مناسب للإنتاج (Stateless API يحتاج Passport/Sanctum مع HTTPS) | أمني — لكنه تصميم للتطوير المحلي |

## الملخص التنفيذي

**Beza** هي منصة مالية رقمية متكاملة مصممة خصيصاً للسوق العربي (سوريا أولاً). تتميز بـ:

1. **محفظة مزدوجة (SYP/USD)** تحل مشكلة تذبذب العملة
2. **تحويل P2P مجاني 0%** — أقل بكثير من المنافسين
3. **شبكة وكلاء** — شمول مالي لمن لا يملكون حسابات بنكية
4. **استثمار حلال** — تمويل تجاري فعلي (وليس فوائد أو Crypto)
5. **ذهب وفضة عيني** — ادخار في أصل ملموس
6. **بوابة دفع للتجار** — مدمجة بدون وسيط
7. **توثيق شامل جداً** — ~1,172 ملف تغطي كل شيء

**التحدي الأكبر:** العقوبات الدولية على سوريا قد تمنع تشغيل بعض الخدمات (Stripe, Twilio, Shufti Pro). الحل: تبني بدائل محلية أو APIs متوافقة مع العقوبات.

## التحول من Sanctum إلى JWT (Authentication Migration)

تم تحويل نظام المصادقة من **Laravel Sanctum** إلى **JWT (JSON Web Tokens)** باستخدام حزمة `tymon/jwt-auth`.

### التغييرات الرئيسية

| العنصر | قبل (Sanctum) | بعد (JWT) |
|--------|---------------|-----------|
| Middleware | `auth:sanctum` | `auth:api` |
| إنشاء التوكن | `$user->createToken(...)->plainTextToken` | `JWTAuth::fromUser($user)` |
| صيغة التوكن | `1\|token_string` | `eyJ... (JWT encoded)` |
| صلاحية التوكن | غير محدودة (يدوياً) | محدودة (60-1440 دقيقة) |
| تخزين التوكن | جدول `personal_access_tokens` | لا حاجة (stateless) |
| تسجيل الخروج | حذف من قاعدة البيانات | إبطال (invalidate) + blacklist |
| الحالة (State) | Stateful (يخزن في DB) | Stateless (مشفر ذاتياً) |
| الميزة | بسيط، مناسب لتطبيقات SPA | أقوى، مناسب للـ API-first |

### نصائح التنفيذ

1. ثبّت الحزمة: `composer require tymon/jwt-auth`
2. انشر الإعدادات: `php artisan vendor:publish --provider="Tymon\JWTAuth\Providers\LaravelServiceProvider"`
3. غيّر `config/auth.php`: `'driver' => 'jwt'` في guard `api`
4. عدّل `User` model: implements `JWTSubject`
5. ولّد مفتاح سري: `php artisan jwt:secret`
6. في Flutter/React: استخدم حزمة `flutter_jwt` أو خزّن التوكن في `flutter_secure_storage`
7. في React: استخدم axios interceptor لإضافة `Authorization: Bearer {token}` تلقائياً
