## 🔄 دورة العمل الكاملة (6 مراحل)

| # | المرحلة | الوصف | بوابة الجودة |
|---|---------|-------|-------------|
| 1 | استلام الأمر وتحليل المتطلبات | قراءة الأمر، تحليل التوافق المعماري، تحديد النطاق | وضوح النطاق، عدم تعارض مع المعمارية |
| 2 | كتابة التوثيق أولاً (Docs-First) | إنشاء `docs/tasks/{unit}/{task-code}.md` بالكامل | اكتمال API/DB/Security/Tests/Sequence |
| 3 | التنفيذ البرمجي | كود داخل `app/Modules/{Unit}/` فقط | `php artisan test` + `analyze` بدون تحذيرات |
| 4 | الفحص والتحقق المحلي | اتصال API + تدفق كامل + مطابقة للتوثيق | 100% مطابقة بين الكود والتوثيق |
| 5 | رفع الكود وإدارة الفرع | `feature/{code}-{name}` → commit → push | الفرع جاهز للمراجعة |
| 6 | كتابة التقرير النهائي | القالب الموحد: مقاييس، روابط، نتائج | التقرير جاهز للتسليم |

## 📄 قالب التقرير الموحد

```
# تقرير تسليم المهمة [رقم/كود المهمة]
المرحلة المنفذة: [اسم المرحلة]
الروابط المرجعية: [رابط التوثيق، رابط الكود، رابط الـ Branch]
المقاييس: [عدد الملفات، الأسطر، الاختبارات، نسبة النجاح]
التدفق المختبر: [وصف السيناريو]
المشاكل والحلول: [عقبات + معالجة]
بوّابات الجودة: [نعم/لا] اختبارات ✅ — مطابقة ✅ — Analyze ✅
الخطوة التالية المقترحة: [مهمّة منطقية تالية]
```

## ✅ نقاط التفتيش الإلزامية

- [ ] التوثيق مكتمل في `docs/tasks/` ويغطي API، DB، Security، Tests
- [ ] الكود داخل مجلد الوحدة فقط — لا استدعاء مباشر بين وحدات
- [ ] العمليات المالية تستخدم bigint (فلس) أو Money Value Object
- [ ] جميع الواجهات تدعم العربية + RTL افتراضياً
- [ ] جميع الاختبارات تنجح 100% بدون تحذيرات
- [ ] رسالة الالتزام: `feat(unit): task-code description | ref: docs/tasks/...`
- [ ] التقرير بالقالب الموحد وجاهز للمراجعة
